# Three Souls 개발 기록

기사·궁수·마법사 세 영웅이 함께 던전을 탐험하는 Android 픽셀 판타지 RPG의 구현과 문제 해결 기록입니다. 기록 정리일은 2026-10-14입니다.

[소개 페이지](https://zjavm8702.github.io/ThreeSouls/) · [체험 APK](https://github.com/zjavm8702/ThreeSouls/releases/tag/portfolio-v1.0) · [프로젝트 소개](../README.md)

## 게임의 방향

핵심 흐름은 **마을에서 준비 → 던전 선택 → 자동 이동·전투와 스킬 사용 → 전리품 획득 → 장비·성장 정비 → 재출정**입니다. 기본 공격과 이동은 자동으로 진행하고, 플레이어는 장비, 직업별 스킬, 룬, 공급품을 통해 파티를 준비하고 전투에 개입합니다.

영웅은 기사·궁수·마법사의 세 직업입니다. 레벨·경험치는 부대 전체가 공유하고, 능력치 강화와 장비는 영웅별로 관리합니다. 던전은 폐광·잊힌 유적·정령의 숲·얼음 협곡의 네 지역과 총 20개 캠페인 스테이지 데이터로 구성했습니다.

## 구현 과정

### 1. 전투와 전리품

세 영웅의 이동·공격, 직업별 스킬과 효과, 전투 결과와 보상을 연결했습니다. 획득 장비와 장착 상태를 저장 데이터로 관리하고, 장비 교체와 성장에 따른 능력치 계산이 연결되도록 구성했습니다. 전투 보상과 경험치 지급을 부대 단위로 처리하여 같은 보상이 여러 영웅을 거치며 중복 지급되지 않도록 했습니다.

### 2. 마을과 출정 준비

마을의 NPC 의뢰, 장비 상점, 룬 제작·강화, 인벤토리, 영웅 성장과 던전 선택을 하나의 플레이 흐름으로 연결했습니다. 회복 물약을 편성하고 자동 회복 기준을 정하는 출정 준비 화면을 추가했습니다. UI는 uGUI와 TextMeshPro를 사용하며 프리팹에서 지정한 이미지·색·배치를 유지하도록 런타임 동작과 외형 편집을 분리했습니다.

### 3. 데이터와 저장

Google Sheets 원본을 CSV·JSON·ScriptableObject 데이터로 가져오는 흐름을 구성했습니다. UI와 상태 문구는 문자열 테이블과 생성 C# 키로 관리합니다. 로컬 저장·백업·복구, 이전 저장의 마이그레이션, 클라우드 기록 충돌 확인을 구현했습니다.

### 4. Android 빌드와 배포

IL2CPP ARM64와 업로드 키 서명을 사용하는 Android APK / AAB 빌드 흐름을 구성했습니다. 게임 씬과 콘텐츠는 원격 Addressables로 분리하고, 콘텐츠 빌드 성공 뒤 GitHub Pages에 자동 게시합니다. 포트폴리오 APK에는 별도 컴파일 정의를 적용하여 Google 로그인·Unity 클라우드 저장·실제 광고를 비활성화했습니다.

## 주요 문제와 해결

### 사례 1 — 설치 파일에 중복 포함되던 콘텐츠

**문제:** Addressables를 원격으로 지정해도 빌트인 마을 씬과 부트스트랩 UI의 참조를 통해 게임 이미지와 폰트가 플레이어에 중복 포함됐습니다.

**수정:** 마을·전투 씬을 원격 씬으로 옮기고 플레이어에는 시작 씬만 포함했습니다. 패치 UI에 필요한 리소스는 별도 부트스트랩으로 관리했습니다. 빌드 전후에 원격 자산의 앱 포함 여부와 오래된 로컬 staging 번들을 검사하도록 했습니다.

**확인:** 당시 서명 AAB의 실제 크기를 118,654,760바이트에서 54,224,298바이트로 약 **54.3% 감소**시켰습니다. 등록 Addressables와 원본 게임 이미지·폰트의 플레이어 포함 0, 원격 카탈로그 경로, 서명과 ARM64 라이브러리 정렬을 확인했습니다. 이는 해당 AAB 비교 결과이며 공개 APK의 크기와는 구분합니다.

### 사례 2 — 마을에 돌아오면 사라지던 스프라이트

**문제:** 첫 진입에서는 정상이어도 전투 후 마을 재진입 때 일부 NPC의 텍스처가 없어져 검은 실루엣으로 나타났습니다.

**수정:** 자산·씬과 아틀라스 의존 관계를 주소 메타데이터로 생성했습니다. 표시 자산의 소유 기간과 아틀라스 수명을 연결하고, 씬 전환이 완료된 뒤 해제하도록 했습니다. Unity의 아틀라스 요청 등록 콜백으로 재진입 시 텍스처 연결을 복구했습니다.

**확인:** Packed Play에서 반복 전투·마을 복귀 후 영웅·NPC 텍스처와 스킬 효과 표시를 확인했습니다. Editor 검증 결과를 모든 실기기에서의 검증으로 확대하지 않았습니다.

### 사례 3 — 원본은 보이지만 번들 UI는 보이지 않던 문제

**문제:** 원본 프리팹에서는 로비 UI가 보였지만, 기존 번들에 저장된 `localScale=(0,0,1)`로 인해 Packed Play에서는 UI가 사라졌습니다. 원래 배율에 값을 곱하는 계산은 0을 복구하지 못했습니다.

**수정:** 런타임 화면 맞춤에서 XY 배율을 직접 계산했습니다. 앵커·피벗·위치와 사용자가 편집한 프리팹 외형은 유지하고, 편집 중 자동 스타일 적용은 제거했습니다. Editor 기본 Play는 Asset Database를 사용하도록 정리했습니다.

**확인:** 마을·인벤토리·캐릭터·준비·지도 다섯 화면과 재활성화 후 크기·배율·앵커·위치를 확인했습니다. 긴 화면과 모의 안전 영역도 별도로 확인했습니다.

### 사례 4 — 팝업 뒤 버튼이 눌리던 문제

**문제:** 룬 제작 후보가 확인창보다 나중에 추가되어 팝업 위로 보이거나 입력을 받았습니다. NPC 대화창의 Dim은 화면 전체를 덮지 않았습니다.

**수정:** 확인창은 열 때마다 마지막 sibling으로 올렸습니다. NPC 대화는 전체 Stretch 모달로 분리하고 Dim이 헤더·하단 탭까지 입력을 받도록 했습니다. 마을 페이지 전환 시 모달을 닫고 소유 객체가 파괴될 때 함께 정리했습니다.

**확인:** Raycast를 통해 팝업이 먼저 입력을 받는지 확인했고, 취소 시 재화가 바뀌지 않는지 검사했습니다. Android Back은 맨 위 팝업 닫기, 종료 확인, 취소 동작으로 연결했습니다.

### 사례 5 — Google 플랫폼 연결과 클라우드 인증의 차이

**문제:** Google Play Games는 연결돼도 Unity 인증이 `id provider is not active`로 거절되는 경우가 있었습니다. 플랫폼 연결과 클라우드 연결을 같은 상태로 취급하면 버튼 표시도 잘못됐습니다.

**수정:** GPGS 연결과 Unity 클라우드 인증 상태를 분리했습니다. 제공자의 Enabled 상태를 확인하고, 기기별 연결 해제 의도를 저장하여 재시작 때 자동 재연결되지 않도록 했습니다. 연결 해제는 원격 계정·저장 삭제와 구분했습니다.

**확인:** 별도 로그인 빌드의 실기기에서 인증·클라우드 백업·해제·재연결·재시작 상태 복원을 확인했습

## 검증 범위

| 구분 | 확인한 범위 |
| --- | --- |
| 코드 / 빌드 | Unity 컴파일, Android 빌드 결과, 서명 검사, 패키지·SDK·아키텍처 |
| Editor Play | 로비 화면, 반복 전투·마을 복귀, 팝업 입력 차단, 저장·성장 경계, 다운로드 진행 |
| 기존 로그인 APK | 실기기 GPGS / Unity 인증, 클라우드 백업, 연결 해제·재연결·상태 복원 |
| 공개 체험 APK | 로그인 없는 마을 진입, 로컬 전용 안내, 온라인 계정 버튼 숨김, 기존 진행 유지 |
| 미검증 / 범위 밖 | 전체 20스테이지 완주, 모든 Android 기기, Play 스토어 정식 설치본, 공개 스토어 출시 |

사용자 진행을 검증용으로 초기화하지 않도록 Editor 테스트는 별도 저장 경로를 사용했습니다. 빌드 성공, 콘텐츠 게시 성공, 실기기 기능 확인은 서로 다른 결과로 기록합니다.

## 포트폴리오 체험판

- Android 8.0 이상 / ARM64, 세로 화면
- 첫 실행에 원격 콘텐츠 다운로드 필요
- 기기 로컬 저장·백업·복구
- Google 로그인·클라우드 저장·실제 광고 비활성화
- 앱 삭제·기기 변경 시 기록 복구 불가
- Google Play 정식 출시본이 아닌 공개 APK

공개 소스는 저장소에 커밋된 프로젝트 스냅샷이며, APK는 2026-10-14 로컬 작업본을 별도 빌드했습니다. GitHub 문서와 소개 페이지에 개인 계정 식별자, 인증 토큰, 서명 비밀번호, 로컬 저장 파일을 포함하지 않습니다.

게임 시스템·UI·데이터·빌드 흐름의 구현 기록입니다. 외부 픽셀 아트·UI·폰트 리소스와 생성 이미지를 사용했으며 모든 시각 자산을 직접 제작했다고 주장하지 않습니다.
